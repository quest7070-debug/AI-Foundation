# Development handoff
Use to turn an observed issue, failing test or narrow request into a development-ready candidate.

1. Verify the current repository, issue or test evidence with the existing CODE read capability when granted.
2. State objective, target scope, source revision, known dependencies, and minimal deterministic acceptance tests.
3. Identify existing behavior to preserve, failure modes, and expected evidence of completion.
4. Send the candidate only through the existing development owner and reviewed task contract. This skill does not create a task queue or start Kandev sessions.
5. Do not merge, deploy, issue Native signals, widen Guard scopes, or send private context to external models.
6. A candidate or passing CI is not proof of a deployed and independently verified result.
