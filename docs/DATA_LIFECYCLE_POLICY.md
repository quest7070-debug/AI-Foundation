# Data lifecycle and deletion ownership

This policy separates authority from derived state. It does not give AI Foundation permission to delete another owner's data.

- Foundation authority/audit (`guard.db` effects/approvals/cancellations, unresolved reconciliation and inference evidence) is preserved until an explicit cross-table retention contract exists. Terminal transient inference evidence, expired claims and consumed human input are the only age-based Foundation deletions currently authorized by `RetentionService`.

- Terminal task intake/work is operational state, not history. `TaskIntake.purge_terminal()` deletes the terminal intake/work/input rows and their status-scoped notification-dismissal cache in one SQLite owner transaction.
- LibreChat Mongo is chat-history source authority. LibreChat's `mongoMeili` owner propagates deletion to Meili; Foundation only observes that relationship. RAG/pgvector is a separate RAG owner and must never be cleaned through the chat-index path.
- Attachment handoff text is a Foundation-derived copy. Owner-scoped upstream deletion removes an inactive materialized handoff; active leases defer deletion. Source uploads are never deleted by Foundation.
- Push dedup, health evidence and presentation/notification UI state are derived operational metadata. They are bounded or removed with their owning terminal subject; they are not audit authority.
- Foundation backups are immutable point-in-time recovery generations. A source deletion does not rewrite an existing backup. Deleted data can therefore remain inside retained backup generations until the backup owner policy removes that generation. Backup generation retention is owner-scoped and preserves protected LKG/newest generations. Restoring an old generation intentionally restores its historical point-in-time contents; this is a recovery action, not silent resurrection by a derived cache.
- Native credentials are not copied into Foundation backups. Restoring provider registry metadata cannot restore a revoked credential: execution eligibility requires the current native secret, and stale restored registry rows fail preflight and are reconcilable as missing credentials.
- Generic storage lifecycle code may classify external state but may not mutate it. Docker/model/search/RAG owners retain their own deletion/rebuild authority.
