# HumanModel project references in the daily Operator

The daily Operator is independently owned on port 8766. The Native release on
8768 has a separate launchd identity, codebase and state. HumanModel integration
changes only the exact daily LaunchAgent after independent staging; no Native
signal, consent, worker or release file is changed.

The additive launcher pins the existing daily script and every legacy package
module. It installs a subclass of the existing AutoCapabilityAgent in its own
process, then executes the unchanged original Operator script. Existing tool
registration, inference routing, repository paths and state remain owned by
the legacy runtime. New source modules live in a separate internal software
directory. Original sources, derived indexes and content-free audit receipts
remain on the existing external HumanModel volume.

The active scope is `ai-foundation-project`, view `foundation-project-reference`.
It contains only two excerpts from pinned GitHub project documentation at
`387ecfcad4cbfae06252e1f01f41e7fb91ee1eab`, classified as shareable project
observations. These are the same project documents already available in the
authorized development context. Existing private owner originals are preserved
and excluded from this binding; they are not reclassified or copied into the
shareable view. Private contexts still require a confined local model.

Tools take only an approved scope, query and bounded page offset. Owner, view,
root and privacy ceiling come from the host binding. Source/Guard admission and
post-retrieval freshness checks remain in the existing HumanModel adapter.
The current response model consumes only the permitted project evidence.

Staging checks exact live daily PID/listener ownership, source and LaunchAgent
hashes, server-side owner identity, source projection, Cognee retrieval, and an
actual legacy-agent tool loop with a synthetic model. No service is restarted
during staging. This synthetic model check is not a real-model acceptance.

Activation requires an idle daily Operator and unchanged Native PID ownership.
It retains the original LaunchAgent and performs a bounded daily restart. The
real HTTP chat test must produce a new owner-bound source-read audit event and
cite at least one complete evidence ID. Otherwise the original daily definition
and prior binding state are restored and readiness is checked again. Only the
ordinary launchd label is reachable through this cutover. Full response text
stays in a private host file; Actions receives structural proof only.

The read-only readiness audit selects the explicitly bound view when multiple
views exist, recognizes the additive launcher, and checks the real server owner.
Code/source readiness does not grant Native authority. Later changes to the
legacy source require a new reviewed stage; the launcher refuses source drift.

The original gateway's five-second CSRF lookup rendered the entire Operator page.
A real M1 read-only probe timed out before signature verification or model execution.
The additive daily runtime exposes the same CSRF token at a loopback, Host-validated
endpoint without rendering operational state. The gateway keeps its original script,
signing, upstream and arguments, and loads only the updated CSRF helper through a
hash-checked launcher. Both original LaunchAgent definitions are backed up and
restored on failed cutover. Native service 8768 is outside both transactions.

A live metadata probe confirmed that local-general still referenced a missing 9B file while Ollama contained existing 2B and 4B models. Discovery now withdraws only host-configured absolute artifact paths that are absent. It preserves existing unloaded files, host role assignments, and the canonical choice among remaining eligible routes. It does not install or restore a model. The legacy launcher applies the same availability check through an additive discovery subclass.

Slow agent runs produce bounded stack metadata after 60 seconds. Records contain module basenames, functions and line numbers; prompts, outputs, frame locals and secrets are excluded. Source-read audit receipts remain a separate authority boundary.

Live acceptance completed on 2026-11-03 through the signed gateway: the ordinary current router fell back from a timed-out free NVIDIA route to the existing free OpenRouter route, invoked both HumanModel search and original-context tools, and cited both project evidence IDs. Two AVAILABLE owner-bound source calls were verified; no private originals were shared and no model was downloaded. The request took about 106 seconds, so this verifies integration rather than a latency target.

The workflow now defaults to read-only deployment verification. It compares deployed code with the checked-out runtime files, rechecks owner/binding/current shareable originals, verifies the earlier live receipt and fast CSRF path, and makes no new model call. Manual stage, activate and recover operations must be selected explicitly.
